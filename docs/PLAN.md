## 1. Objective & Positioning

Build a Redis-compatible server from scratch in Go (RESP protocol, ~40 commands, TTL, persistence, eviction, transactions, replication) plus the **Antares Observatory** — a separate showcase/tooling service and web UI that visualizes the server's internals and proves its claims live.

**Why this project wins SDE-1 interviews (India, product companies):**
- Replication (PSYNC/backlog) is the most differentiating SDE-1 project feature; very few candidates can discuss it from implementation experience.
- Every claim is machine-verifiable: differential tests vs real Redis, crash tests, benchmarks, CI-verified numbers displayed in the UI.
- The Observatory converts internal correctness work (WAL frames, eviction sampling, expirations) into a visible demo — story #5 ("cut the replica link, watch partial resync") is unforgettable in a project deep-dive.
- 4 living docs (ADR log, session log, file manifest, interview Q-bank) turn engineering artifacts into rehearsed interview answers.

**Scope decision:** v1 + v2 + v3 including replication (ADR-012).

## 2. What "Done" Means (Definition of Done)

**Server (`make verify` — one command, all green):**
- redis-cli compatible: PING/ECHO/SET/GET/... work interactively; `redis-cli --stat` clean.
- Differential tests vs real Redis 7.4 pinned in docker: **0 mismatches** across all implemented commands.
- Official Tcl test suites: `unit/expire` and `unit/type/incr` **fully pass**; broader subsets documented.
- Crash test: 100× SIGKILL at random points; **zero acked-write loss** with `fsync=always`; ≤1s window with `everysec`.
- Benchmarks: **≥50–80% of real Redis throughput** (targets: P=1 60–100k rps, P=16 400–800k rps), median of 3 runs, methodology + variance documented in `BENCHMARKS.md`.
- Race detector clean; 1h RESP parser fuzz clean; replication dataset-equality tests green.

**Antares Observatory (`make showcase` — one command):**
- Fresh clone → docker compose demo profile → open localhost:8080 → seeded data + guided tour.
- All 6 demo stories pass Playwright E2E in CI: (1) side-by-side differential, (2) TTL lifecycle, (3) eviction under pressure, (4) crash lab zero-loss, (5) replication continuity (+CONTINUE vs +FULLRESYNC), (6) transaction visualizer.
- Every number rendered in the UI comes from `claims.json` generated by `make verify` — no hand-typed values.
- UI: initial JS < 250KB gz (enforced in CI), axe a11y pass, graceful degradation (event tap off → polling; no real Redis → compare hidden).

## 3. Architecture Overview

### 3.1 Server
- **Concurrency (ADR-002):** goroutine per connection for I/O → command channel → **single executor goroutine owning the keyspace**. Redis-like sequential semantics; race-detector clean by construction.
- **Protocol (ADR-003):** RESP2 (inline, bulk strings, arrays, integers) + `HELLO` downgrade stub so modern redis-cli works.
- **Storage:** Go maps/slices; TTL dict; no listpack/intset encodings (documented non-goal). Empty collections auto-delete on last element removal.
- **Expiration (ADR-005):** lazy on access + active cycle (hz=10, sample 20 keys, repeat if >25% expired).
- **Persistence (ADR-004):** AOF = append-only framed log `[u32 len][u32 CRC32][RESP payload]`, group commit, fsync policies `always/everysec/no`; recovery replays until first bad CRC then truncates (torn-tail); rewrite/compaction via snapshot when thresholds hit.
- **Eviction (ADR-006):** maxmemory enforcement; approximated LRU (24-bit clock, sample 5, eviction pool); policies `noeviction` (default), `allkeys-lru`, `volatile-lru`.
- **Transactions:** MULTI/EXEC/DISCARD with dirty+EXECABORT semantics; WATCH via value-snapshot compare (ADR-008, documented divergence).
- **Replication:** `REPLICAOF`, PSYNC handshake, `master_repl_offset`, 1MB backlog ring, `+FULLRESYNC` via shared snapshot format (ADR-007), `+CONTINUE` partial resync, `REPLCONF ACK` every 1s, replica read-only (`-READONLY`), output buffer caps for slow replicas.
- **No fork (ADR-010):** snapshot = executor copy + write buffering; bounded pause; overflow policy documented.
- **Event tap (ADR-014):** opt-in `--event-log path.jsonl` (off by default, nil-sink overhead), rotated, versioned schema: cmd, frame, fsync, expire, evict, repl_sync, repl_ack, aof_recover.

### 3.2 Antares Observatory (UI workstream)
- **`cmd/observatory` bridge process (ADR-013):** never embedded in the server.
  - Reads: own `internal/client` → Antares AND real Redis (side-by-side); tails `--event-log` JSONL; polls INFO at 4Hz; reads `claims.json`.
  - Serves: static SPA + REST (`/api/exec`, `/api/keys`, `/api/info`, `/api/topology`, `/api/claims`, `/api/lab/*` gated by `DEMO_MODE=1`) + SSE stream (`/api/events/stream`).
  - Transport: SSE + REST (ADR-015).
- **SPA (ADR-016):** React + TypeScript + Vite + Tailwind + uPlot + TanStack Query/Virtual. Sections: Overview, Playground, Keyspace, Replication Lab, Durability Lab, Metrics/Bench, Decision Journal (renders DECISIONS.md), Interview Mode.
- **Trust mechanism (ADR-018):** hero metrics render only from `claims.json` {value, source command, timestamp, commit}; unverified claims never render.

### 3.3 Data flow
```
redis-cli/clients ──RESP──▶ Antares ──▶ event tap (JSONL, opt-in)
go-redis (verify) ──RESP──▶ Antares + real Redis (differential)
Observatory ──internal/client──▶ Antares & real Redis
Observatory ──tail JSONL + INFO poll + claims.json──▶ SPA (SSE + REST)
```

### Session protocol (10 / 100 / 30)
- **Start (10 min):** re-read last PROJECT_LOG entry + today's subphase exit criterion. `make test` baseline green.
- **Build (100 min):** the harness writes all code (implementation, tests, CI, docs). **Defend-rule (never ship code you can't defend 10 min):** the critical path — RESP parser, WAL/frames + recovery, expiry, eviction, transactions, replication handshake/backlog — gets a mandatory line-by-line owner review before it ships; the owner may also write any file directly.
- **Close (30 min):** run exit tests; append PROJECT_LOG (what built, files touched, bugs: symptom→diagnosis→fix→prevention, ADRs written); update FILE_MANIFEST; refresh QBank from the session's decisions and corrections; write tomorrow's first task.

### Phase gate (mandatory before advancing)
1. Exit criteria green (command evidence logged).
2. Docs updated (no orphan files in manifest; new decisions logged).

## 9. Verification Strategy (pyramid, all CI-enforced)

1. **Unit tests** (fast, table-driven) — colocated with the package under test (Go convention); `tests/unit/` is reserved for cross-package suite-level tests.
2. **Differential vs real Redis** (ADR-017: independent go-redis client, pinned Redis 7.4) — response canonicalization rules in harness config; 0 mismatches.
3. **Official Tcl suites subset** — `unit/expire`, `unit/type/incr` (+ documented broader subset); pinned versions vendored.
4. **Chaos** — kill -9 matrix (100×), torn-write injection, replica kill/reconnect (50×), split-brain; `chaos.yml` nightly.
5. **DST shadow model** — randomized interleavings vs in-process HashMap reference (transactions, expiry, eviction interactions).
6. **Fuzz** — RESP parser + frame recovery; regression corpus grows in-repo.
7. **Benchmarks** — median of 3, variance reported, context (machine, Go version) recorded; raw outputs in `bench/results/` keyed by commit.
8. **UI verification** — Playwright E2E per story in demo stack, axe a11y, bundle budget (250KB gz), golden screenshots; graceful-degradation tests (tap off, no real Redis).
9. **Claims pipeline** — `make verify` writes `claims.json` {value, command, timestamp, commit, variance}; UI renders only from it.

## 10. Benchmark Methodology & Anchors

- Tool: `redis-benchmark` against Antares AND real Redis, same machine, quiet, 3 runs, median.
- Workloads: `SET`/`GET` P=1 and P=16, 1e6 requests (smoke) / 5e6 (final), 50 clients; plus MGET/INCR mix.
- **Anchors (context, not targets to beat):** Redis docs non-pipelined SET ~72–180k rps; MacBook Air P=16 pipelined SET 1.53M / GET 1.81M rps; published from-scratch Go/Rust servers reach 77–99% of Redis (redis-rust paper, 2-CPU Docker).
- **Our targets:** P=1 60–100k rps; P=16 400–800k rps; ≥50–80% of real Redis on same box.
- Honesty rules: report GC pause impact if visible, never cherry-pick, variance stated; methodology section in `BENCHMARKS.md` copied into claims metadata.

## 12. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Schedule overrun (20+ weeks) | Timebox S2.2 (W19 freeze rule); M1/M2 features individually droppable; M1/M2 are demo-able waypoints for applications |

| Differential canonicalization rabbit holes (SCAN order, float formats, INFO) | Canonicalization rules centralized + reviewed (ADR-017 area); per-family timebox 1 session |
| Tcl suite version drift | Pin Redis 7.4 docker image + vendored test files commit hash |
| Mid-project motivation dip (P6 AOF grind) | M1 dev console exists by then; every session ends with visible progress; stories demo-able |
| AI over-dependence ("can't defend code") | Hand-own rule on critical path |
| Benchmark noise on macOS | Quiet runs, 3-run median, report context honestly (no CPU pinning on mac) |
| UI scope creep | ADR-019 non-goals; 250KB budget; each story must map to a QBank probe |
| Real Redis 7.4 divergence with newer Redis docs | Pin version everywhere; note doc/version in COMPATIBILITY.md |
