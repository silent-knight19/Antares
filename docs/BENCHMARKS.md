# Antares Performance & Benchmarks (PLAN §10, ADR-018)

> **Methodology**: Core benchmarks use `redis-benchmark` comparing Antares against reference Redis 7.4.11 on the same machine. Replication benchmarks use one Antares master with and without one attached replica. Every run uses 50 concurrent client connections and 3 iterations, reporting median throughput (requests/second), variance, latency percentiles (p50, p99 in milliseconds), and offset lag.
>
> All numbers below are machine-generated by `make bench` (`bench/scripts/run-bench.sh` and `bench/scripts/run-repl-bench.py`) and tracked in `claims.json` with commit and timestamp provenance.

---

## 1. Environment & Anchors

- **Platform**: `darwin/arm64` (Apple Silicon)
- **Go Toolchain**: `go1.27.1` (pinned in `go.mod`)
- **Reference Redis**: Redis 7.4.11 (pinned Docker image `sha256:4fa24486b8bcca8eec45ee0eb166edc674795e53a2b53d1a9ef263eecebaac85`)
- **Benchmark Tool**: `redis-benchmark`
- **Workloads**: `PING_INLINE`, `PING_MBULK`, `SET`, `GET`, `INCR`, `MSET`, `LPUSH`, `RPUSH`, `LPOP`, `RPOP`, `SADD`, `HSET`, `SPOP`
- **Concurrency**: 50 clients, 3 runs, median reported

### Target Anchors (PLAN §10)
- **Sequential (P=1)**: Target **60,000 – 100,000 rps** (or ≥50% of reference Redis)
- **Pipelined (P=16)**: Target **400,000 – 800,000 rps** (or ≥50% of reference Redis)

## 3. Replication Throughput & Lag (S3.2)

**Setup**: one Antares master, `redis-benchmark -t set` at P=1 and P=16, 50 clients, 50,000 requests per run, 3 runs per condition. The baseline phase runs against the master with no replica; the loaded phase attaches one Antares replica with `REPLICAOF` and waits for `master_link_status:up` and equal offsets before every run. Both phases `FLUSHALL` before each run. The same master process serves both phases, so the comparison isolates the cost of feeding one replica.

**Lag sampling**: every 50 ms during the loaded phase, `INFO replication` is read from the master and replica; lag is `master_repl_offset - slave_repl_offset` in bytes. After `redis-benchmark` exits, catch-up time is measured until the replica reaches the master's offset. The replica stayed connected and caught up after every run.

| **P=16** | **866,551** | **567,537** | **65.5%** | **34.5%** | 4,864 | 23,983 |

## 4. How to Reproduce

Run the full benchmark suite:

```bash
make bench
```

To run with custom iteration counts or request depths:

```bash
BENCH_REQUESTS=100000 BENCH_RUNS=3 make bench
```

To run only the replication throughput/lag suite (no Docker required):

```bash
make bench-repl
REPL_REQUESTS=1000000 REPL_RUNS=3 make bench-repl
```

To run the complete verification umbrella including tests, diff harness, Tcl suites, crash tests, fuzz smoke, and benchmarks:

```bash
make verify
```
